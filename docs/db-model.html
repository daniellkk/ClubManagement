How the outside systems link to a fan

customerId is the Excel "Customer no." = Eventim CustNr = the number after the club prefix in Fortress member ids (SHF_12345). The club prefix in Eventim / Fortress is SHF. It is on every fan and never changes.
  • Eventim Inhouse (EvaXML): nightly, SearchEvents for the season window, then per game FetchTicketData from the game's stored timestamp. Every ticket carries CustNr, so rows attach to the fan directly. Season-ticket seats show up on every home game with SubscriptionFlag.
  • Fortress: the scan log per game (barcode, turnstile, time) fills Attendance. That endpoint is not integrated anywhere yet; until it is, attendance stays unknown rather than assumed. FullActiveExtract on the member product gives card numbers per customer.
  • WooCommerce: every order carries billing.email, billing.phone and a name; registered buyers also carry the WordPress customer_id, guests carry 0. WooCommerce has no customer number, so the club adds one optional field ("מספר לקוח") to the account / checkout, stored as order meta (_club_customer_number). We match customer number → email → phone, first hit wins, and write which one matched (matchedBy). No hit: the order is kept with an empty fanId and appears in an "unmatched" list to link by hand; a later order from the same email links the earlier ones too.
  • App: same rule, customerId → email → phone, one AppUser row per account.
  • Loading the Excel: one merged row = one Fan upsert (by Customer no.) + one FanSeason row for that season. Column names in FanSeason are the Excel's. Load the three seasons oldest first; the status column is then computed against the season before.

Nightly sync

  1. Games: Eventim SearchEvents for the season dates → upsert Game by eventimEventId. Home / away comes from VenueShortCode (Turner = home); competition and opponent are set once by an admin.
  2. Tickets: per game, FetchTicketData with the stored timestamp → upsert Ticket by (game, barcode), then save the returned NewTimestampUTC on the game. Status V = valid, S = cancelled; rows with sales channel 6000 are skipped, as the current middleware does.
  3. Attendance: per played game, Fortress scan log → upsert Attendance by (fan, game). Member barcodes change their first digit on reprint, so match member rows by customer no. + row + seat, not by barcode.
  4. Store: WooCommerce GET /wc/v3/orders?status=any&modified_after=<cursor>&per_page=100, page by page → upsert StoreOrder by wooOrderId and its lines by wooLineItemId; the cursor is the newest modifiedAt we hold, so refunds and cancellations come through as updates. Line items carry no category, so /products/{id} is looked up once per product (cached) to fill category. Optional: the order.created / order.updated webhooks (HMAC-SHA256 signed) push the same upsert during the day.
  5. Aggregates: recompute Game.ticketsSold / attendance and the fan's engagement score. The club's own points rule fits here: 50 points for the first membership season, 10 per further season, and each game 5 points for members, 1 for others.
  6. Contacts on demand: the Eventim customer endpoint (GetCustomerDataInhouseInt?CustomerNo=…) refreshes one fan's email and phones when an admin asks. One call per customer, so not a nightly job.

Credentials for Eventim (username / password per club), Fortress (basic auth + app id + API key per stadium) and WooCommerce (a read-only consumer key / secret from WooCommerce → Settings → Advanced → REST API, plus the webhook secret) live in a secret store, never in the database. The Eventim customer endpoint is on a non-standard port and is expected to be IP-whitelisted; WooCommerce must be called over HTTPS.

Club, AdminUser, Tag, Campaign, MessageLog, ConsentLog, ImportJob and AuditLog already exist and stay as they are. Subscription is replaced by FanSeason; Shuttle is dropped. ActivityEvent stays: it is the dashboard's recent-activity list, written by imports, campaign runs, the game sync and the score job.

Against today's Prisma schema, Fan keeps legacyId and lastActivityAt, renames memberSince → firstSeenAt, and gains source and enrichedAt; Game gains capacity, goalsFor, goalsAgainst; StoreOrderItem is new.
